# GPU Cluster & AI Infrastructure Paper Tracker

An automated DBLP paper tracker for GPU clusters and AI infrastructure. It follows the systems stack from accelerators and high-performance networking through distributed training, inference serving, resource scheduling, cloud orchestration, and Kubernetes.

## Research Scope

- GPU cluster scheduling, placement, sharing, and utilization
- Distributed and parallel training infrastructure
- LLM inference, model serving, and serving optimization
- Collective communication, RDMA, and network-performance engineering
- Kubernetes-based AI cluster orchestration
- AI accelerators, memory systems, and high-performance computing

## Features

- Searches a curated set of AI-systems, operating-systems, cloud, networking, HPC, and architecture venues every day
- Keeps papers from the last three years through the next year
- Deduplicates records by publication URL and title, including across search topics
- Fetches abstracts and DOI metadata, extracts GitHub repository links, and optionally translates abstracts into Chinese with Qwen-MT-plus
- Regenerates `FL-Papers.md` as a categorized AI-infrastructure reading list
- Opens a GitHub Issue when new papers are found

## Tracked Venues

- **AI / ML Systems:** MLSys, NeurIPS, ICML, ICLR
- **Cloud & Operating Systems:** OSDI, SOSP, EuroSys, USENIX ATC, SoCC, Middleware
- **Networking & Communication:** NSDI, SIGCOMM
- **High-Performance Computing:** SC, HPDC
- **Architecture & Accelerators:** ASPLOS, ISCA, MICRO, HPCA
- **Systems Journals:** ACM TOCS, IEEE TPDS

The keywords and venue restrictions live in [`config.yaml`](config.yaml). The current keywords cover GPU clusters, scheduling, distributed/parallel training, inference serving, collective communication, RDMA, Kubernetes, and tensor/pipeline parallelism.

## Run Locally

```bash
pip install -r requirements.txt
cd src
python main.py run --env=dev
```

Normal runs scan every configured `keyword × venue` combination. The narrower `--primary_only` compatibility mode remains available for single-theme configurations, but is intentionally not used by the scheduled workflow because AI infrastructure contains several independent subfields.

For a safe connectivity check, open **Actions → Run DBLP Watch → Run workflow** and keep `smoke_test` enabled. This performs one `GPU cluster × MLSys` query with at most 10 results and does not update the cache, fetch abstracts, commit files, or create an Issue.

The existing cache can be retained when changing domains. Only topics generated by the current keywords and venues participate in deduplication and Markdown generation, so legacy federated-learning records do not contaminate the AI-infrastructure results.

For deployment, configuration, and maintenance details, see [`TECHNICAL.md`](TECHNICAL.md).

# GPU 集群与 AI 基础设施论文追踪器

这是一个面向 GPU 集群与 AI Infrastructure 的自动化 DBLP 论文追踪器，覆盖从加速器、高性能网络，到分布式训练、推理服务、资源调度、云平台和 Kubernetes 的完整系统链路。

## 研究范围

- GPU 集群调度、任务放置、资源共享与利用率优化
- 分布式训练与并行训练基础设施
- 大模型推理、模型服务与推理性能优化
- 集合通信、RDMA 与网络性能工程
- 基于 Kubernetes 的 AI 集群编排
- AI 加速器、内存系统与高性能计算

## 主要能力

- 每日检索 AI 系统、操作系统、云计算、网络、HPC 和体系结构领域的精选 venue
- 仅保留近三年至未来一年的论文
- 按论文链接和标题去重，并支持跨检索主题的全局去重
- 自动补充摘要和 DOI、提取 GitHub 代码链接，并可通过 Qwen-MT-plus 翻译中文摘要
- 将 `FL-Papers.md` 重新生成成按领域分类的 AI Infra 阅读清单
- 发现新论文时自动创建 GitHub Issue

## 追踪会议与期刊

- **AI / ML 系统：** MLSys、NeurIPS、ICML、ICLR
- **云与操作系统：** OSDI、SOSP、EuroSys、USENIX ATC、SoCC、Middleware
- **网络与通信：** NSDI、SIGCOMM
- **高性能计算：** SC、HPDC
- **体系结构与加速器：** ASPLOS、ISCA、MICRO、HPCA
- **系统期刊：** ACM TOCS、IEEE TPDS

关键词和 venue 限制位于 [`config.yaml`](config.yaml)。当前关键词覆盖 GPU 集群与调度、分布式/并行训练、推理服务、集合通信、RDMA、Kubernetes，以及张量/流水线并行。

## 本地运行

```bash
pip install -r requirements.txt
cd src
python main.py run --env=dev
```

日常任务会完整扫描所有 `关键词 × venue` 组合。项目仍保留适用于单一主题的 `--primary_only` 兼容模式，但定时工作流不会启用它，避免遗漏 AI Infra 各并列方向的论文。

如需安全测试 GitHub 网络连接，可打开 **Actions → Run DBLP Watch → Run workflow**，并保持 `smoke_test` 开启。该模式只执行一次 `GPU cluster × MLSys` 查询，最多返回 10 条结果，不更新缓存、不抓取摘要、不提交文件，也不创建 Issue。

切换研究领域时可以保留原缓存；去重和 Markdown 生成只读取当前配置对应的检索主题，因此旧的联邦学习记录不会混入新的 AI Infra 结果。

部署、配置与维护说明请参阅 [`TECHNICAL.md`](TECHNICAL.md)。
