# AI Infrastructure Paper Tracker

An automated DBLP paper tracker for AI infrastructure. It follows the complete systems stack from accelerators and high-performance networking through distributed training, inference serving, resource management, cloud orchestration, and Kubernetes.

This repository is the automated candidate-paper pipeline for [Awesome-AIInfra](https://github.com/lys122519/Awesome-AIInfra). Watch this tracker for real-time discovery notifications; use Awesome-AIInfra for the reviewed and curated collection.

## Research Scope

- Compute-resource scheduling, placement, sharing, and utilization
- Distributed and parallel training infrastructure
- LLM inference, model serving, and serving optimization
- Collective communication, RDMA, and network-performance engineering
- Kubernetes-based AI cluster orchestration
- AI accelerators, memory systems, and high-performance computing

## Features

- Reads DBLP's official monthly XML snapshot and filters a curated set of AI/ML, NLP, retrieval, multimodal, systems, networking, HPC, and architecture venues locally
- Applies configurable title exclusions and requires infrastructure context for broad method keywords such as quantization, mixture-of-experts, model compression, and long context
- Keeps papers from the last three years through the next year
- Deduplicates records by publication URL and title, including across search topics
- Fetches abstracts and DOI metadata, extracts GitHub repository links, and optionally translates abstracts into Chinese with Qwen-MT-plus
- Regenerates `AIInfra-Papers.md` as a categorized AI-infrastructure reading list
- Opens a GitHub Issue when new papers are found

## Tracked Venues

- **AI / ML Systems:** MLSys, NeurIPS, ICML, ICLR, AAAI, IJCAI
- **NLP & Language Models:** ACL, EMNLP, NAACL, EACL, COLING, TACL, Computational Linguistics
- **Data, Search & Web:** KDD, SIGIR, WWW, ACM TOIS, IEEE TKDE
- **Multimodal & Vision:** CVPR, ICCV, ECCV, IEEE TPAMI
- **ML & AI Journals:** JMLR, IEEE TNNLS, Artificial Intelligence
- **Cloud & Operating Systems:** OSDI, SOSP, EuroSys, USENIX ATC, SoCC, Middleware
- **Networking & Communication:** NSDI, SIGCOMM
- **High-Performance Computing:** SC, HPDC
- **Architecture & Accelerators:** ASPLOS, ISCA, MICRO, HPCA
- **Systems Journals:** ACM TOCS, IEEE TPDS

The keywords and venue restrictions live in [`config.yaml`](config.yaml). The current keywords cover compute-resource management, distributed/parallel training, LLM serving and efficiency, model compression, quantization, speculative decoding, KV-cache management, mixture-of-experts, collective communication, RDMA, Kubernetes, and model parallelism.

Filtering rules live under `dblp.filters`. `exclude_title_keywords` removes unwanted areas such as federated learning, while `require_any_by_keyword` requires broad method names to appear with a systems or efficiency signal. After changing these rules, apply them to existing data and rebuild the paper list:

```bash
python scripts/filter_cache.py
python scripts/convert_cache_to_md.py
```

The curated output includes main proceedings, Findings, and industry tracks. Workshops, demos, posters, tutorials, student tracks, companion volumes, and position papers are explicitly excluded. To prepare a review batch for [Awesome-AIInfra](https://github.com/lys122519/Awesome-AIInfra):

```bash
python scripts/export_candidates.py --year 2025 --venue MLSys --venue OSDI --output candidates.yaml
```

Exports are marked unreviewed by default and must go through an Awesome-AIInfra pull request before publication.

## Run Locally

```bash
pip install -r requirements.txt
python scripts/sync_dblp_snapshot.py
cd src
python main.py run --env=dev
```

The first command downloads about 1 GiB once; later runs reuse the same monthly release. Normal runs stream the snapshot once and distribute records across every configured `keyword × venue` combination. The narrower `--primary_only` compatibility mode remains available for single-theme configurations, but is intentionally not used by the scheduled workflow because AI infrastructure contains several independent subfields.

For a safe connectivity check, open **Actions → Run DBLP Watch → Run workflow** and keep `smoke_test` enabled. It discovers the latest official release, performs a HEAD check, and runs the bundled parser tests. It does not download the large dump, update the cache, fetch abstracts, commit files, or create an Issue.

This design follows DBLP's bulk-access guidance and does not automate or bypass its interactive verification challenge. The scheduled workflow runs monthly, matching the snapshot release cadence.

Only topics generated by the current keywords and venues participate in deduplication and Markdown generation. Reset `cached/dblp.yaml` when starting a new research scope if you also want to reclaim repository space.

For deployment, configuration, and maintenance details, see [`TECHNICAL.md`](TECHNICAL.md).

# AI 基础设施论文追踪器

这是一个面向 AI Infrastructure 的自动化 DBLP 论文追踪器，覆盖从加速器、高性能网络，到分布式训练、推理服务、资源管理、云平台和 Kubernetes 的完整系统链路。

本仓库是 [Awesome-AIInfra](https://github.com/lys122519/Awesome-AIInfra) 的自动化候选论文管线。关注本仓库可获得实时发现通知；Awesome-AIInfra 则维护经过人工审核与整理的正式知识库。

## 研究范围

- 算力资源调度、任务放置、资源共享与利用率优化
- 分布式训练与并行训练基础设施
- 大模型推理、模型服务与推理性能优化
- 集合通信、RDMA 与网络性能工程
- 基于 Kubernetes 的 AI 集群编排
- AI 加速器、内存系统与高性能计算

## 主要能力

- 使用 DBLP 官方月度 XML 快照，在本地筛选 AI/ML、NLP、检索、多模态、系统、网络、HPC 和体系结构领域的精选 venue
- 支持可配置的标题排除规则，并要求量化、混合专家、模型压缩和长上下文等宽泛关键词同时具备基础设施语境
- 仅保留近三年至未来一年的论文
- 按论文链接和标题去重，并支持跨检索主题的全局去重
- 自动补充摘要和 DOI、提取 GitHub 代码链接，并可通过 Qwen-MT-plus 翻译中文摘要
- 将 `AIInfra-Papers.md` 重新生成成按领域分类的 AI Infra 阅读清单
- 发现新论文时自动创建 GitHub Issue

## 追踪会议与期刊

- **AI / ML 系统：** MLSys、NeurIPS、ICML、ICLR、AAAI、IJCAI
- **NLP 与语言模型：** ACL、EMNLP、NAACL、EACL、COLING、TACL、Computational Linguistics
- **数据、检索与 Web：** KDD、SIGIR、WWW、ACM TOIS、IEEE TKDE
- **多模态与视觉：** CVPR、ICCV、ECCV、IEEE TPAMI
- **机器学习与 AI 期刊：** JMLR、IEEE TNNLS、Artificial Intelligence
- **云与操作系统：** OSDI、SOSP、EuroSys、USENIX ATC、SoCC、Middleware
- **网络与通信：** NSDI、SIGCOMM
- **高性能计算：** SC、HPDC
- **体系结构与加速器：** ASPLOS、ISCA、MICRO、HPCA
- **系统期刊：** ACM TOCS、IEEE TPDS

关键词和 venue 限制位于 [`config.yaml`](config.yaml)。当前关键词覆盖算力资源管理、分布式/并行训练、LLM 服务与效率、模型压缩、量化、投机解码、KV Cache、MoE、集合通信、RDMA、Kubernetes 和模型并行。

## 本地运行

```bash
pip install -r requirements.txt
python scripts/sync_dblp_snapshot.py
cd src
python main.py run --env=dev
```

首次同步会下载约 1 GiB 的压缩快照，后续运行会复用同一个月度版本。程序只流式读取快照一次，再将论文分配到所有 `关键词 × venue` 组合。项目仍保留适用于单一主题的 `--primary_only` 兼容模式，但定时工作流不会启用它，避免遗漏 AI Infra 各并列方向的论文。

如需安全测试 GitHub 网络连接，可打开 **Actions → Run DBLP Watch → Run workflow**，并保持 `smoke_test` 开启。该模式仅发现最新官方版本、执行 HEAD 校验并运行内置解析测试，不下载大型快照，不更新缓存、不抓取摘要、不提交文件，也不创建 Issue。

该方案遵循 DBLP 对批量访问的建议，不会自动处理或绕过交互式验证挑战。定时工作流改为每月运行，与快照发布节奏一致。

过滤规则位于 `config.yaml` 的 `dblp.filters`。修改规则后，可运行 `python scripts/filter_cache.py` 清理已有缓存，再运行 `python scripts/convert_cache_to_md.py` 重新生成论文列表。

正式候选列表收录主会、Findings 和 Industry Track；Workshop、Demo、Poster、Tutorial、Student Track、Companion Volume 和 Position Paper 会被明确排除。可通过 `scripts/export_candidates.py` 为 Awesome-AIInfra 生成待审核批次，导出内容默认不会被标记为已审核。

去重和 Markdown 生成只读取当前配置对应的检索主题；切换研究范围时可以重置 `cached/dblp.yaml`，同时回收仓库空间。

部署、配置与维护说明请参阅 [`TECHNICAL.md`](TECHNICAL.md)。
